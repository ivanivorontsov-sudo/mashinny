# Спецификация «Машинного» 0.1

## 1. Представления программы
Главная форма программы — бинарный файл `.pnb`. Текст служит только для чтения и бывает двух видов: канонический (`mash fmt`) и компактный (`mash fmt --compact`). Оба вида без потерь переводятся в один и тот же `.pnb`, и обратно:

- `to-bin(text)` детерминирован: пробелы, переносы и порядок функций в тексте на байты не влияют, функции сортируются по имени;
- `from-bin(b)` выдаёт канонический текст, `to-bin(from-bin(b)) == b`;
- декодер строгий: он отвергает неминимальный LEB128, лишние байты, неизвестные теги, неотсортированные функции, неверный UTF-8 и имена, а в конце сверяет, что повторное кодирование даёт ровно те же байты (`B-NONCANON`). Поэтому каждой программе соответствует одна последовательность байтов.

### Формат `.pnb`
```
"PNB" 0x01
uleb len(code) ; code
names
code  = uleb nfuncs, затем для каждой функции: uleb len, тело функции
func  = str name, uleb nparams, type*, type ret, uleb effects, uleb flags(pre=1,post=2,dec=4), [pre] [post] [dec] body
names = uleb n, str*  (имена параметров, let и лямбд в порядке обхода)
```
Переменные кодируются индексами де Брёйна, поэтому секция `code` не зависит от имён локальных переменных.
- `hash` — SHA-256 всего файла;
- `semantic_hash` — SHA-256 секции `code`: переименование локальных переменных его не меняет (как в Unison);
- `functions` — хеш каждой функции.

Целые числа хранятся как zigzag + LEB128 и могут быть любой длины до 4096 бит. Строки хранятся как длина + UTF-8.

Теги типов: Int 0, Bool 1, Str 2, Unit 3, List 4+T, Ui 5. Теги узлов: 0x10 Int, 0x11 true, 0x12 false, 0x13 Str, 0x14 unit, 0x15 Var, 0x16 вызов функции, 0x17 встроенная, 0x18 бинарная операция, 0x19 отрицание, 0x1A not, 0x1B if, 0x1C let, 0x1D список, 0x1E лямбда.

## 2. Синтаксис
```
fn ИМЯ(п: Тип, ...) -> Тип [!io] [pre BOOL] [post BOOL] [dec INT] = ВЫРАЖЕНИЕ
```
Выражения: литералы, переменные, вызовы `f(a, b)`, `if c then a else b`, `let x = e; тело`, списки `[a, b]`, лямбды `|x: T| e` (только как аргумент `map`, `filter` и `fold`), операции `+ - * / % == != < <= > >= && || ! ++`.
Приоритеты от слабых к сильным: `||`, `&&`, сравнения, `++`, `+ -`, `* / %`, унарные. Все операции левоассоциативны. Комментариев в языке нет: текст — это вид бинарника.
Грамматика: `mash grammar` (GBNF для llama.cpp) и `mash grammar --format json-schema` (JSON-схема AST для structured output).

## 3. Типы
Int (длинное целое), Bool, Str (последовательность кодовых точек Unicode), Unit, `[T]`, Ui. Неявных преобразований нет. Ошибки выдаются в JSON:
```json
{"code": "E-UNBOUND", "message": "unknown variable", "at": {"line": 1, "col": 27}, "path": "fn f/body/left", "got": "coutn", "fix": "replace with `count`"}
```
Коды ошибок: E-LEX, E-PARSE, E-CANON, E-TYPE, E-UNBOUND, E-ARITY, E-EFFECT, E-NODEC, E-MUTREC, E-DUP, E-SHADOW, E-RESERVED, E-EMPTYLIST, E-LAMBDA, E-NOEQ.

## 4. Семантика
- Нет неопределённого поведения. `/` и `%` — деление с округлением вниз (как в Python), деление на ноль — ловушка `T-DIV0`. Числа длиннее 4096 бит — ловушка `T-BIG`. `wrap64(x)` даёт явное 64-битное переполнение в дополнительном коде.
- Нет неупорядоченных коллекций: порядок всегда определён, `sort` детерминирован.
- Эффекты явные: `print` разрешён только в функции с `!io`. При `predict` эффекты записываются в журнал и не выполняются.
- Тотальность. Рекурсия разрешена только прямая и только с мерой `dec`. Взаимная рекурсия запрещена. Циклов нет, есть `map`, `filter` и `fold` по конечным спискам. `mash prove` доказывает через Z3, что мера неотрицательна и убывает. Кроме того, у каждого запуска есть лимит шагов (`--fuel`, по умолчанию 1 000 000) и глубины вызовов (10 000), поэтому любая программа завершается.
- Шаги считаются одинаково во всех движках: 1 шаг за каждый вычисленный узел плюс длина обрабатываемых данных у операций со списками и строками.
- Контракты `pre` и `post` (в `post` доступно `result`) и мера `dec` проверяются при каждом запуске (ловушки T-PRE, T-POST, T-DEC) и статически через `mash prove`.

## 5. Предсказание
`mash predict` возвращает точный результат: значение, число шагов, журнал эффектов или ловушку. Те же данные дают `run`, байткод-VM и нативный AOT-бинарник; это проверено тестами.

## 6. Детерминированный интерфейс (Ui)
Элементы: `rect(id, w, h, цвет)`, `text(id, строка, цвет, масштаб)`, `button(id, надпись)`, `col(отступ_между, поля, фон, [дети])`, `row(...)`, `stack([дети])` (наложение, позже = выше), `at(x, y, ui)`, `clip(id, w, h, ui)`. Цвет задаётся как 0xRRGGBB, фон −1 значит прозрачный.
- Координаты только целые, округлений нет. Шрифт встроенный, растровый 6×12 (Spleen, BSD-2), с латиницей и кириллицей; размер текста = 6·len·масштаб × 12·масштаб.
- Порядок по z = порядок обхода дерева. Обрезка — пересечение с прямоугольником `clip` и экрана.
- Растеризация программная, в RGBA, бит в бит одинаковая на всех машинах; хеш = SHA-256(ширина, высота, пиксели).
- `mash predict файл --ui 360x240 --ui 1024x600 --hit 245,75 --png-dir out --map` выдаёт для каждого размера экрана: рамку каждого элемента, видимую область, число видимых пикселей, кем элемент перекрыт, кто получит клик в точке, карту владельцев пикселей (RLE), PNG и хеш. Окно для этого не открывается.

# Язык программирования «для ИИ»: исследование и план (25.10.2026)

## 1. Что может значить «язык для ИИ»
**(а) Язык, который ИИ (LLM) надёжно пишет и читает.** Цели: мало токенов, нет неоднозначностей, обязательные типы и контракты, понятные ошибки компилятора с готовым исправлением, документация в формате для агентов (SKILL.md/AGENTS.md).
- Vera (2026, MIT): контракты и эффекты, проверка через Z3, компиляция в WebAssembly, файлы SKILL.md и AGENTS.md — https://github.com/aallan/vera , https://veralang.dev
- Almide: ошибки компилятора называют исправление, выход в Rust и Wasm — https://github.com/almide/almide
- SLOP: S-выражения, обязательные @intent/@pre/@post, «дыры» с типами для дописывания моделью, вся спецификация ~4K токенов — https://github.com/slop-lang/slop
- Tacit (LLVM, экономия токенов) — https://github.com/weetster/tacit ; TML (MCP-сервер встроен в компилятор) — https://github.com/hivellm/tml
- Каталог подобных языков: https://agentlanguages.dev
- Jac (Jaseci, `by llm`) — https://www.jac-lang.org

**(б) Язык или DSL для работы с LLM, промптами и ML.**
- BAML: типизированные LLM-функции, тесты, генерация SDK для Python и TS; v1 вышел в публичную бету как полноценный язык — https://docs.boundaryml.com , https://boundaryml.com
- LMQL (https://lmql.ai), Guidance (https://github.com/guidance-ai/guidance), SGLang (https://github.com/sgl-project/sglang), Outlines: ограниченная генерация (регулярки, JSON) на локальных моделях.
- DSPy: сигнатуры и оптимизаторы промптов — https://dspy.ai
- Prompty (https://github.com/microsoft/prompty), POML (Microsoft), Pkl (конфиги, https://pkl-lang.org)
- Сравнение подходов: https://boundaryml.com/blog/structured-output-from-llms

**(в) Язык для построения ИИ и ML.** Mojo (https://www.modular.com/mojo), Triton (https://triton-lang.org), JAX (https://jax.readthedocs.io). Это огромная работа уровня компиляторов (MLIR, GPU), для одного человека за 1–2 дня нереально.

**(г) Язык для агентов и оркестрации инструментов.** Шаги, вызовы инструментов через MCP (https://modelcontextprotocol.io), повторы, бюджеты, разрешения. Близкие проекты: BAML v1 (`spawn`/`await`), Jac.

## 2. Путь реализации
- **Грамматика.** Lark (Python, EBNF, быстро — https://lark-parser.readthedocs.io); ANTLR (многоязычный — https://www.antlr.org); tree-sitter (подсветка и редакторы — https://tree-sitter.github.io); ручной Pratt-парсер (лучшие сообщения об ошибках). Совет: ручной парсер для компилятора и tree-sitter только для подсветки.
- **Цель компиляции.** Транспиляция в Python или JS (MVP, сразу доступны библиотеки ИИ) → байткод-VM → Wasm или LLVM/MLIR (только позже).
- **Редакторы.** LSP через pygls (https://github.com/openlawlibrary/pygls) или vscode-languageserver (Node), расширение VS Code, грамматика TextMate.
- **Инструменты.** Форматтер (одно каноническое форматирование, полезно для LLM), golden-тесты (вход → ожидаемый вывод), фаззинг парсера.
- **Пакеты.** PyPI (pyproject и `pipx install`) или npm (bin).
- **Репозиторий.** `spec/`, `src/`, `tests/`, `examples/`, `docs/`, `editors/vscode/`, `SKILL.md`, `AGENTS.md`, `LICENSE` (MIT или Apache-2.0), GitHub Actions для тестов на Linux и Windows. Actions экономить: лимит бесплатных минут уже на 90%.

## 3. Понятный — основа уже есть
`/workspace/ponyatny`, репозиторий github.com/ivanivorontsov-sudo/ponyatny, версия синтаксиса 2.0. Там уже есть лексер, парсер, AST, семантическая проверка, генерация JS, сборка в .exe, переводчик Python/JS/C# и песочница на Vercel. В `ik2` есть подсветка.
Новый язык можно сделать (1) диалектом или расширением Понятного с ИИ-конструкциями или (2) отдельным языком, переиспользуя устройство компилятора Понятного: лексер → парсер → проверка → JS. Это в разы быстрее, чем начинать с нуля.

## 4. Варианты на выбор
**A. «Понятный-ИИ» (рекомендую).** Расширение Понятного с русскими словами для LLM-функций и агентов, компиляция в JS/Node:
```
схема Отзыв
    оценка: число от 1 до 5
    кратко: строка
конец
ии-функция разбери(текст: строка) -> Отзыв
    модель "ollama:qwen2.5:3b"
    промпт "Разбери отзыв: {текст}"
конец
агент Помощник
    инструменты: поиск, калькулятор
    бюджет: 10 шагов
конец
тест разбери("Отлично!").оценка >= 4
```
Плюсы: опирается на готовый компилятор, уникален (русский BAML), бесплатные локальные модели через Ollama. Минусы: малая аудитория за пределами русскоязычных.

**B. Язык, который пишет сам ИИ (как Vera или SLOP).** Отдельный минимальный язык с жёстким синтаксисом, обязательными контрактами и ошибками в JSON с готовым исправлением, транспиляция в Python. Плюсы: модная ниша 2026 года. Минусы: конкуренция, пользы для самого Ивана меньше.

**C. Язык агентов и оркестрации.** YAML-подобный или Понятный-синтаксис для сценариев: шаги, MCP-инструменты, разрешения, повторы, бюджеты. Плюсы: практично. Минусы: близко к существующим фреймворкам.

## 5. MVP на 1–2 дня (вариант A)
1. Ветка или новый репозиторий `ponyatny-ii`, лицензия MIT.
2. Добавить в лексер и парсер Понятного конструкции `схема`, `ии-функция`, `тест`; `агент` пока необязателен.
3. Генерация JS: вызов OpenAI-совместимого API (по умолчанию Ollama на localhost), JSON-schema из `схема`, проверка ответа и до 2 повторов.
4. Команды CLI `ponyatny-ii запустить` и `проверить`, понятные русские ошибки.
5. 15–20 golden-тестов и тест с подменённой моделью без сети; CI только на Linux.
6. README, 3 примера, SKILL.md (спецификация до ~3K токенов, чтобы ИИ сам мог писать на языке).
После MVP: LSP и расширение VS Code, tree-sitter, форматтер, пакет в npm, агенты с MCP.

Ограничения: публикации на GitHub и сборки пока не делались, всё это только исследование.

# 6. Главное требование Ивана: «бинарность», чтобы ИИ предвидел результат на 100%

## 6.1 Каноническая бинарная форма
- Один байткод на программу. Текст → AST → нормализация (сортировка, единые имена) → байты. У одной программы всегда ровно одна кодировка, поэтому код можно сравнивать побайтно.
- Образцы:
  - WebAssembly: компактный бинарный формат и детерминированный профиль — https://webassembly.github.io/spec/
  - детерминированный (канонический) CBOR, RFC 8949 §4.2 — https://www.rfc-editor.org/rfc/rfc8949#section-4.2
  - Unison: функция идентифицируется хешем своего AST, имена — только метки — https://www.unison-lang.org/docs/the-big-idea/
- Предложение: формат `.pnb`. Заголовок, версия, канонический CBOR-список функций, SHA-256 содержимого как идентификатор. Есть обратный перевод в текст: `разобрать`/`собрать` дают одинаковые байты туда и обратно (round-trip).

## 6.2 Полностью детерминированная семантика (никакого UB)
- Целые фиксированной ширины (i64/u8 и т.д.). Переполнение задано явно: ошибка, «по кругу» или насыщение, по аналогии с Rust checked/wrapping/saturating.
- Дробные: десятичные с фиксированной точностью (decimal) или IEEE-754 со строгими правилами: одно правило округления, канонический NaN, без FMA-сюрпризов.
- Никакого скрытого ввода-вывода: время, сеть, файлы и ИИ доступны только как объявленные эффекты. Случайность — только `случайное(зерно)`.
- Порядок обхода словарей детерминирован (порядок вставки или сортировка).
- Эффекты указаны в типе функции (`функция f() ! сеть, файл`). Чистая функция без эффектов предсказуема полностью.
- Тотальность: рекурсия только структурная, циклы только по конечным коллекциям, либо «топливо» — лимит шагов. Исчерпанный лимит даёт определённый результат `ошибка: топливо`, а не зависание.
- Нет потоков с гонками: параллельность только детерминированная (fork-join с фиксированным порядком результатов).

## 6.3 Инструменты предсказуемости
- Формальная small-step семантика (правила переходов в `spec/`), например в стиле WebAssembly spec или K Framework — https://kframework.org
- Эталонный интерпретатор, написанный прямо по этим правилам. Компилятор в JS проверяется против него дифференциальным тестированием.
- Анализатор эффектов и стоимости: точное или верхнее число шагов, память, список эффектов (как gas в EVM).
- `предсказать файл.pon`: «сухой прогон», который даёт точный вывод, число шагов и хеш результата без реальных эффектов. Эффекты подменяются записанными ответами (record/replay).
- Property-тесты (fast-check, https://fast-check.dev ; Hypothesis, https://hypothesis.works).
- Контракты `требует`/`гарантирует`, проверяемые SMT-решателем Z3 (https://github.com/Z3Prover/z3), в духе Dafny (https://dafny.org) и Vera.

## 6.4 Честно о пределах
Проблема остановки: для произвольной программы на тьюринг-полном языке нельзя заранее гарантировать результат. 100% предсказуемость достижима так:
1. **Тотальное подмножество** (как Dhall — https://dhall-lang.org, Agda/Idris total): все программы завершаются, результат — функция от входа.
2. **Ограничение топливом**: каждая программа имеет лимит N шагов, поэтому результат («значение» или «топливо кончилось») всегда определён и воспроизводим.
3. **Внешние эффекты** (сеть, ответ LLM) по природе непредсказуемы. Предсказуемым становится всё, кроме их ответов. При записанных ответах (replay) прогон точный, а ответ ИИ можно сделать воспроизводимым через temperature 0, seed и кэш, хотя провайдеры это гарантируют не всегда.
Гарантия: детерминизм эталонного интерпретатора + канонический байткод + хеш (программа, вход, топливо, записи эффектов) → один и тот же результат всегда. Проверяется тестом «запустить 1000 раз на разных ОС — одинаковый хеш».

# 7. Обновлённая рекомендация (бинарность — в центре)
**Вариант A′ «Понятный-ИИ / Точный» (рекомендую).** Русский текстовый синтаксис на базе Понятного → канонический байткод `.pnb` → детерминированная VM (JS, позже Wasm). Чистое тотальное ядро и топливо по умолчанию. ИИ-вызовы — объявленный эффект `ии` с записью и повтором. Команда `предсказать` выдаёт точный результат.
**Вариант B′ «Язык для машин».** Минимальный S-выражений/AST-first язык, где бинарная форма первична, а текст лишь вид. Контракты с Z3, тотальность обязательна. Максимальная предсказуемость, но людям читать тяжелее.
**Вариант C′ «Детерминированные агенты».** DSL сценариев агентов поверх детерминированного ядра: каждый шаг журналируется, весь прогон воспроизводится повтором по журналу.

## MVP 1–2 дня (A′)
1. Подмножество Понятного: числа i64 с ошибкой при переполнении, decimal, строки, списки, словари с порядком вставки, функции, `если`, `для каждого`; без `пока`, кроме случая с топливом.
2. Канонический энкодер AST → CBOR → `.pnb`, хеш SHA-256 и round-trip тест.
3. Эталонная стековая VM на JS с топливом (по умолчанию 1 000 000 шагов).
4. Эффекты в сигнатуре; `напиши`, `ии`, `случайное(зерно)` работают через журнал эффектов.
5. `ponyatny-ii предсказать` выдаёт вывод, шаги и хеш; `запустить` даёт тот же хеш.
6. 30 golden-тестов и property-тест «VM == компилятор в JS»; CI только на Linux.
Позже: Z3-контракты, формальная спецификация, Wasm-бэкенд, LSP.
